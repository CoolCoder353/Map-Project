# The server's move to maps.coolcodertech.com (2026-10-26)

What changed when the live server's address moved from `maps.paulsjones.com` to
`maps.coolcodertech.com`, why, and what it broke or left to do.

## What moved, and what didn't

| | Before | After |
|---|---|---|
| Public address | `https://maps.paulsjones.com` | `https://maps.coolcodertech.com` |
| Way in | Router TCP 443 → nginx Proxy Manager (192.168.50.34, proxy host 8) → CT 112 port 8080 | Cloudflare (HTTPS, WAF) → Cloudflare Tunnel (`cloudflared` on CT 112) → port 8080 |
| Name resolution | cPanel/Synology DDNS, AdGuard rewrite on the LAN | Cloudflare DNS |
| Server, containers, database, map data | CT 112 (`maps`, 192.168.50.7) | **Unchanged**: same CT, same containers, same database |

**Why:** done by the migration team to take the server off the home router's port 443 and the
nginx proxy, and put it behind Cloudflare.

## Data

Nothing needed copying: both addresses reach the same containers and the same PostgreSQL
database, which is the only copy of accounts, trips and feedback. Checked on 2026-10-26:

- The database held 3 users, 206 trips (newest 2026-10-25 21:39 UTC) and 33 feedback items.
  Requests to the new address are served by the same API and database (Caddy's logs show both
  hosts).
- A full dump was taken before anything else changed:
  `/root/wayfinder-2026-10-26-host-migration.sql.gz` on the server (25 MB, all tables including
  `places`, complete to the end). It and the 2026-10-01 dump were world-readable and are now
  readable by root only.
- `infra/.env` on the server already had `PUBLIC_URL=https://maps.coolcodertech.com`, so the API
  hands out style and tile URLs at the new address and accepts browser requests only from it.

The server still has no scheduled backups ([deploy-small-server.md](deploy-small-server.md#open-items)):
the dump is a one-off on the same disk.

A new APK installed over the old one would have kept using it and stopped working when the old address goes. It now switches to the new address and keeps the sign-in (same server, same tokens). ## Problems the move causes

1. **Play reviewers are blocked.** Cloudflare's WAF lets in Australian visitors only. Google's
   reviewers and URL checkers are mostly elsewhere, so the privacy policy and deletion page would
   fail Play's checks, and a reviewer can't sign in. Fix for the pages: add
   `and not http.request.uri.path in {"/privacy" "/delete-account"}` to the block rule. Whether to
   let reviewers use the app is a separate decision. Details in the Play log.
2. **Installed apps still use the old address.** Every APK and Play bundle up to versionCode 6 has
   `maps.paulsjones.com` baked in and saved. They keep working only while the old path is up.
   Keep it until everyone has 0.5.1.
3. **The web app at the old address shows no map.** Tiles and styles now come from the new
   address, and CORS allows the web app only there. Signing in and planning work there; the map
   doesn't. Tell web users to use the new address. (Adding the old address to `CORS_ORIGINS` would
   fix it, but the old address is going away.)
4. **The Play listing and forms still name the old address** until changed by hand
   ([console-changes-2026-10-26.md](../store/play/console-changes-2026-10-26.md)).
5. **Port 8080 is still open on the LAN.** Anything on the LAN can bypass the tunnel and WAF.
   Once the old path is gone, publish 8080 on `127.0.0.1` only, since `cloudflared` runs on the
   same CT.

## What the move gains

- HTTPS and DNS are Cloudflare's: no DDNS, no router port 443, no certificate on nginx to renew.
- Cloudflare's WAF and DDoS protection sit in front of the server.
- One less machine (the nginx proxy) on the path to the server.

## Found along the way

- `node_modules` in the repo was owned by root, left by the 2026-10-09 APK build, so `pnpm install`
  and the Jest suite failed. Ownership was given back to the user. Watch for it after the next
  `build-apk.sh`.
